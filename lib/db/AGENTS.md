# Database agent guide

This package owns PostgreSQL connections, Drizzle's complete schema registry,
migrations, and WhatsApp webhook persistence.

## Schema ownership

- `src/schema/auth.ts` is generated by Better Auth. Do not hand-edit it; change
  auth configuration and run `yarn auth:generate`.
- `src/schema/mba.ts` contains application-owned chat/channel data. Every
  channel belongs to an `auth.organization`; preserve organization scoping as
  the tenant boundary in reads and writes.
- Export every schema module from `src/schema/index.ts` so runtime Drizzle and
  consumers see the complete registry.
- Keep normalized identifiers/timestamps needed for filtering while preserving
  complete typed provider payloads in JSONB where the model requires lossless
  data.
- Treat provider IDs and unique indexes as idempotency boundaries. Do not let
  out-of-order status events regress the current message projection.
- Keep status history append-only and non-message activity in `chat_events`.
  Preserve the transaction boundaries described in `MBA_MESSAGE_MODEL.md`.

## Migration workflow

1. Change or regenerate the TypeScript schema.
2. Run `yarn db:generate` from the repository root.
3. Review generated SQL and metadata under `drizzle/`; do not accept destructive
   changes without confirming they are intended and safely migrated.
4. Apply locally with `yarn db:migrate` when database access is available.

Do not modify an already-deployed migration to represent a new change; add a
new migration. The runtime migrator must close its connection and fail the app
startup on migration errors.

## Connection and verification

- Keep imports side-effect-light: Postgres.js must continue connecting lazily.
- Production requires an explicit PostgreSQL URL; do not weaken protocol or
  production validation.
- Callers own `closeDatabase()` during graceful shutdown.

```bash
yarn workspace @mba-demo/db typecheck
yarn workspace @mba-demo/db test
yarn workspace @mba-demo/db build
```
